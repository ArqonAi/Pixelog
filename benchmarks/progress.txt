ARCHITECTURE V2 (this session): Turn embeddings + Coref + Facts
=============================================================

Three architectural improvements landed behind the existing
retriever, no API-cost increase at default settings:

1. PER-TURN EMBEDDINGS (internal/bench/hybrid_retriever.go)
   - turnRecord.Embedding []float32 populated by
     embedTurnsConcurrent (8-way bounded concurrency) during
     buildSessionIndex. Query-time cosine against per-turn
     embedding feeds into scoreTurnsGlobal and
     retrieveHybridContext. PixelogConfig.EmbedTurns gates it;
     defaults to true.
   - Paraphrase recall: "What is Caroline's relationship status?"
     now matches "I'm currently single" via cosine, not lexical.
   - Tests: TestTurnEmbeddings_ParaphraseRecall,
     TestEmbedTurnsConcurrent_PopulatesEmbeddings.

2. COREFERENCE RESOLUTION (internal/bench/coref.go)
   - Deterministic, zero-LLM-cost preprocessor. resolveCoref runs
     once per buildSessionIndex and produces per-turn IndexHints
     (resolved speaker / addressee / top-3 recent entities).
   - Hints are appended to turnRecord.IndexText used by BM25 +
     entity + preference + semantic scorers — NEVER shown to the
     answerer (turnRecord.Text stays pristine).
   - Rules:
       "I / me / my"      → speaker
       "you / your"       → every other participant
       "we / us / our"    → speaker ∪ others
       short turn <=8 tok → inherit top-3 recent entities
       3rd-person pronoun → inherit top-3 recent entities
   - Tests: 7 functions in coref_test.go covering each class +
     integration with buildSessionIndex + no-leak guarantee.

3. ENTITY-FACT MICRO-GRAPH (internal/bench/facts.go)
   - Fact{Subject, Predicate, Object, SourceTurnID, Timestamp,
     Confidence, Source} triple schema.
   - FactExtractor interface with ruleFactExtractor: 9 regex
     patterns for high-frequency assertion templates
     (relationship-status, lives-in, moved-from, works-at,
     likes, dislikes, has-job, favorite-X, status).
   - buildFactIndex de-dupes on (subject, predicate) with
     later-supersedes-earlier semantics — captures "I'm dating
     Phil" → later "I'm single" update.
   - Retrieval integration: scoreTurnsGlobal and
     retrieveHybridContext both pre-compute factSourceTurns for
     the query's capitalised entities, then add
     weights.FactBoost (1.5) to each source turn's score. A
     rule-extracted fact match dominates BM25+Keyword combined.
   - Tests: TestRuleFactExtractor_Patterns (6 pattern cases),
     TestBuildFactIndex_Supersession,
     TestFactIndex_LookupBySubject, TestFactIndex_NilSafe,
     TestFactBoost_Integration_RetrieverLiftsSourceTurn.

SESSION 2026-04-28/29 — TEMPORAL CATEGORY DIAGNOSIS + V2.1 ARCHITECTURE
========================================================================

Question asked: "how do we improve the temporal?"

Diagnosis (see this session's chat log)
---------------------------------------
LoCoMo's cat-3 (n=96, our "temporal" label) is COUNTERFACTUAL INFERENCE,
not date arithmetic ("Would Caroline likely have Dr. Seuss books?",
"Would Melanie be considered LGBTQ?"). The actual "When did X happen"
temporal questions live in cat-2 (multi_hop, n=321) where we already
score 95.64% Hit@10. Real bottleneck: hash-similarity ceiling + the
fact-graph not capturing biographical signals (interests, identity,
upbringing).

Fixes shipped this session (all tested, race-free)
--------------------------------------------------
Fix 2 — broaden rule extractor (facts.go)
  + raised-in        "I grew up in / was raised in / was born in X"
  + pursuing         "I'm studying / pursuing / majoring in X"
  + has-interest     "I'm interested in / passionate about X"
  + identifies-as    "I'm a [noun]"
  + owns             "I have / own / bought a X"
  + did-event        "I attended / visited / went to X" (Fix 4 lite)
  6 new predicates with confidence 0.7-0.85.

Confidence-graded fact boost (hybrid_retriever.go, hybrid_context.go)
  Replaced the binary 1.5-flag with FactBoost × per-fact confidence.
  Principled: high-precision rules (LLM=0.9, favorite-X=0.9) pull
  harder than hedged matches (likes=0.75). FactBoost bumped 1.5→1.8
  to compensate for the multiplicative scaling.

Fix 3 wiring — LLMFactExtractor pluggable (adapter.go, hybrid_*.go)
  + PixelogConfig.FactExtractor field
  + buildSessionIndexWith(turns, extractor)
  + multiClientFactCompletion adapter (cmd/pixe-bench/main.go)
  + --llm-facts / --llm-facts-model CLI flags
  + Parallelized buildFactIndex to 8-way concurrency (was sequential
    — would have taken ~30 min per LoCoMo case with LLM extractor)

Embedder hardening (internal/search/embeddings.go)
  + retryableHTTPDo: 4-attempt exponential backoff on 429 + 5xx
  + Wraps OpenAI provider; 4xx not retried (caller errors)
  + 3 unit tests cover recovery, no-4xx-retry, ctx-cancel
  Production-grade fix for the hang we observed at 33min on full
  1986-QA LoCoMo run (one stalled query embedding stalls everything
  because retrieve queries are sequential).

Known remaining issues
----------------------
- Per-QA query embedding is sequential. 1986 QA × ~500ms = 16 min
  baseline before any session/turn embedding. Bumping recall runs
  on the full dataset would benefit from concurrent QA execution
  in the runner.
- embedTurnsConcurrency=8 (and now extractFactsConcurrency=8) may be
  too conservative for OpenAI's effective rate limits.
- The OpenRouter embedding endpoint is wired identically to OpenAI
  but may not be tested under retry; only OpenAI provider has been
  exercised this session.
